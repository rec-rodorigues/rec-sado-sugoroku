# 佐渡すごろく 制作指示書

Oct 11, 2026 · @なはた

## この指示書の使い方

この指示書をMarkdownで書き出し、リポジトリに `docs/SPEC.md` として置いてからClaude Codeに渡す。仕様が変わったら、まずこの指示書を直してから作業を頼む。

Claude Codeへの最初の依頼文の例：

```
docs/SPEC.md を読んで、内容を理解したら「制作フェーズ」の1を作ってください。
分からない点や決まっていない点があれば、作り始める前に質問してください。
```

2回目以降は「フェーズ2に進んで」「マス12の写真を差し替えて」のように、場所と変更内容を1つずつ伝える。

## 企画概要

早稲田大学の理工展（11月）で、環境ボランティアサークルの企画「REC」として展示する、子ども向けのパソコン用すごろくゲーム。RECは佐渡に行って現地の人のお手伝いをする企画で、コンセプトは佐渡の地域活性。

- ゲームの目的：遊びながら佐渡の名所・自然・食べ物を知ってもらい、「佐渡に行ってみたい」と思ってもらう
- 遊び方：2〜4人で、佐渡の実際の地図の上を一周する。止まったマスのイベントでポイントを集め、ゴール時のポイントが一番多い人が勝ち
- 費用：無料で作る（有料のツール・素材は使わない）
- 運用：大枠ができたら、イベント・クイズ・写真はサークルのメンバーが後から追加する
- 参考：以前の試作版（人数選択とターン表示まではある。作り直してよい）
- 公開先：https://rec-rodorigues.github.io/rec-sado-sugoroku/

## 対象とプレイ時間

対象は小学校中学年（3〜4年生）、2人プレイで1回5分前後が目安（全員が楽しめることを優先し、多少超えてもよい）。ここからマス数を40マス前後と決める。

**時間の見積もり**

- 1ターン（サイコロ約2秒＋移動約1秒＋イベント表示5〜10秒）＝平均12〜15秒
- 5分 ÷ 2人 ＝ 1人あたり約10ターン
- サイコロの平均は3.5なので、12ターン × 3.5 ＝ 約42マスで一周
- 3人なら約7〜8分、4人なら約10分になる。会場ではこの目安を掲示する

**中学年向けの配慮**

- 3年生までに習う漢字以外にはふりがなを付ける（HTMLの `<ruby>` を使う）
- 説明文は1〜2文で短く。クイズは3択で、問題文は30字以内を目安にする
- 文字は大きく（本文で画面上18px以上）、ボタンは大きく押しやすくする
- 操作はマウスのクリックだけで完結する。キーボード入力は使わない
- 負けている子も楽しめるよう、ポイントが大きく減るマスや「1回休み」は作らない

## ゲームルール

全員が両津港をスタートし、佐渡を一周して両津港に戻る。ゴール時のポイントが一番多い人が勝ち。

1. タイトル画面でプレイ人数（2〜4人）を選ぶ。各プレイヤーは名前（任意）とコマを選ぶ
2. 順番にサイコロ（1個、1〜6）を振り、出た目の数だけ進む
3. 止まったマスのイベントでポイントが増えたり減ったりする（0未満にはならない）
4. 名所マスは、止まると大きなイベントと写真が出る。通り過ぎたときも、写真つきの小さなカードを2秒ほど表示する
5. ゴールはぴったりでなくてよい。出た目がゴールを超えてもゴールとする
6. トキの森公園・佐渡金山・小木港・岩首昇竜棚田は「かならず止まるマス」。出た目が余っていても、そのターンはそこで止まる
7. ゴールした順にボーナスがもらえる。ゴールした人にも番は回ってきて、全員がゴールするまで、サイコロをふって「出た目×10点」がもらえる（待っているあいだも楽しめるように）
8. 全員がゴールしたら結果発表。ポイントの多い順に表彰台で表示する

同点のときは、先にゴールした人を上位にする。

## マップとルート

OpenStreetMapの地図の上を、下の順に一周する。ルートの大枠は試作版のルートにそろえ、大膳神社と妙宣寺の間に佐渡弁慶 佐渡本店を加える。島の端も回って一周らしくするため、小佐渡の西の海ぞい・沢崎（万畳敷）・宿根木・姫崎も通る（海のぎりぎりを通る必要はない）。合計40マス（両津港1＋名所8＋普通マス31）で、名所と名所の間に普通マスを4つずつ置くのが基本（両津港〜トキの森公園は3つ、大膳神社〜佐渡弁慶〜妙宣寺は2つずつ）。

| 順番 | 名所マス | イベントの案（中身は後で決める） |
| --- | --- | --- |
| スタート | 両津港 | 佐渡汽船で到着。ゴールも兼ねる |
| 1 | トキの森公園 | トキの森公園に行った（かならず止まる） |
| 2 | 大野亀 | 大きな岩と花畑を見に行こう |
| 3 | 佐渡金山 | 金を見つけた（サイコロボーナス・かならず止まる） |
| 4 | 大膳神社 | 能を見た |
| 5 | 佐渡弁慶 佐渡本店 | おいしいお寿司を食べた |
| 6 | 妙宣寺 | 五重塔を見上げよう |
| 7 | 小木港 | たらい舟に乗った（かならず止まる） |
| 8 | 岩首昇竜棚田 | 棚田でおいしいお米を収穫した（かならず止まる） |
| ゴール | 両津港 | 一周おつかれさま。ゴールボーナス |

**地図の作り方**

- 地図はOpenStreetMapの地図（タイル）をそのまま使い、Leaflet（リポジトリ内に保存）で表示する。画面の隅に「© OpenStreetMap contributors」と出典を表示する
- 地図の画像はインターネットから読みこむので、会場ではインターネットが必要。つながらないときは画面にお知らせを出す
- 各マスの位置は緯度・経度（lat, lng）でデータに持つ。名所は実際の場所に置き、普通マスは道路の上に置く
- マスの間は、実際の道ではなく、マスを順につなぐなめらかな曲線で表示する（ルートを見やすくするため）
- 名所マスの名前は、いつも地図にふりがな付きで表示する。かならず止まるマスには「かならず とまる」と出す
- 「編集モード」（URLの末尾に `?edit=1`）では、地図をクリックするとその緯度・経度が表示され、メンバーがマスの位置を決められる

## 演出とUI

「子どもが飽きない動き」と「安っぽく見えない統一感」を最優先にする。

**画面構成（横長のPC画面、1366×768以上を想定）**

- 中央：佐渡の地図。手番のコマを中心にカメラが追いかける
- 上：「〇〇さんの番」を大きく表示（プレイヤーの色つき）
- 右：スコアボード（コマ・名前・ポイント・いまの順位）
- 右下：大きな「サイコロをふる」ボタンとサイコロ

**動き**

- サイコロ：CSSの3Dで立方体を転がし、1.5〜2秒で止まる。止まった目を大きく表示する
- コマ移動：1マスずつピョンと跳ねて進む（1マス約0.3秒）。跳ねるたびに小さな効果音
- カメラ：手番のはじめは、これから進めるマスが入るように合わせる（マスの間が長いところでは縮小し、マスがこみあっているところでは拡大する）。移動中はコマを追いかけ、イベント中は少しズームする
- イベント：写真つきのカードが下から出てくる。ポイントは数字がカウントアップして、スコアボードへ飛んでいく
- 結果発表：表彰台にコマが順番に登場し、紙吹雪を出す

**見た目**

- 色：佐渡の海の青・田んぼの緑・金山の金を基本色にして、全画面でそろえる
- 角丸のカードとボタン、やわらかい影。絵文字はアイコンの代わりに使わない
- フォント：丸ゴシック（例：M PLUS Rounded 1c、無料・OFLライセンス）をPC内に保存して使う
- コマ：4種類のオリジナルキャラ（例：トキ、たらい舟、金のかたまり、おにぎり）。色だけでなく形でも区別できるようにする
- 効果音・BGM：まずはブラウザの機能（Web Audio）で作った音を使う（ファイル不要・ライセンスの心配なし）。無料素材サイトの音に差し替えたいときは、利用規約を確認してから `sounds/` に置き、`js/sound.js` の `SOUND_FILES` に書く。音のON/OFFボタンを付ける

## 技術方針とファイル構成

HTML・CSS・JavaScriptだけで作り、GitHub Pagesで公開する。ゲームの仕組み（プログラム）と中身（データ）を分け、メンバーは `data/` と `images/` だけを触れば内容を追加できるようにする。

**守ること**

- 地図の画像（OpenStreetMapのタイル）以外は、インターネットがなくても動く。フォント・画像・音・ライブラリ（Leafletを含む）はすべてリポジトリ内に置く
- `index.html` をダブルクリックしても動く。そのためデータはJSONではなく `.js` ファイルで持つ
- ビルドやインストールが必要な仕組みは使わない
- データの書き間違いがあっても止まらず、画面に「マス12のデータに問題あり」のように表示する

**ファイル構成**

```
sado_sugoroku/
├── index.html          ← 画面（基本触らない）
├── css/style.css       ← 見た目（基本触らない）
├── js/                 ← ゲームの仕組み（基本触らない）
├── data/
│   ├── squares.js      ← マスの並び・種類・座標
│   ├── events.js       ← イベントの文章・ポイント・写真
│   ├── quizzes.js      ← クイズ問題
│   └── credits.js      ← 写真・地図・音の出典
├── images/places/      ← 現地の写真（横1200px以下のjpg）
├── sounds/             ← 効果音・BGM
└── docs/
    ├── SPEC.md         ← この指示書
    └── HOW_TO_ADD.md   ← メンバー向け「追加のしかた」
```

**データの書き方の例**

```js
// data/squares.js（マス）
{ id: 4, type: "place", name: "トキの森公園", yomi: "ときのもりこうえん", lat: 38.03728, lng: 138.42195, event: "toki" }

// data/events.js（イベント）
{ id: "toki", title: "トキを発見！", text: "ピンク色のつばさが きれいだね。",
  photo: "images/places/toki.jpg", point: 50 }

// data/quizzes.js（クイズ）
{ question: "佐渡で大切に守られている、ピンク色のつばさの鳥は？",
  choices: ["トキ", "ツル", "カモメ"], answer: 0, point: 30 }
```

`docs/HOW_TO_ADD.md` には、プログラムを知らないメンバーでも上の形をまねして追加できるよう、手順と注意点を書く。

## イベントの型とポイント目安

大枠の段階で作るのは「型」とポイントの幅まで。具体的な文章・写真・問題は、大枠ができてからメンバーがデータに追加する。この幅を守れば、誰が追加してもゲームバランスが崩れない。

| マスの種類 | 色 | 起きること | ポイントの幅 |
| --- | --- | --- | --- |
| 名所マス | 金 | 写真つきの大きなイベント | +20〜+100 |
| サイコロボーナス | 金（名所の一部） | もう一度サイコロをふり、出た目×10〜30点（例：佐渡金山は×30） | +10〜+180 |
| ラッキーマス | 青 | 佐渡の小さな出来事（例：ぶりカツを食べた！）。サイコロで当たりが出るとボーナスのものもある（例：流れ星 +50） | +10〜+30 |
| クイズマス | 黄 | 3択クイズ。正解でポイント、不正解は解説を表示 | 正解+30、不正解0 |
| ハプニングマス | 赤 | ちょっとした失敗（例：ビーチクリーンで疲れた）。船よいは次の番の進むマスが1へる | −10〜−20 |
| すすむ・もどるマス | 緑 | 1〜3マス進む、または戻る | なし |
| 決まったマスのイベント | マスの色 | そのマスでいつも起きる（I♥佐渡・棚田じじい・帰りたくない） | −50〜+100、または1〜3マス |
| 野生のトキ | ― | どのマスでも、イベントのあとに5%で出る。I♥佐渡を買った人は10%。1人2回まで | +150 |
| ゴールボーナス | ― | ゴールした順番 | 1着+150、2着+120、3着+80、4着+50 |
| まちじかんボーナス | ― | ゴールした人がほかの人を待っているあいだ、自分の番にサイコロをふる | 出た目×10 |

40マスの内訳の目安は、両津港1・名所8・ラッキー10・クイズ10・ハプニング6・すすむもどる5。クイズは毎回同じにならないよう、10問以上の中からランダムに出す。

**細かい決まり（フェーズ4で決定）**

- すすむ・もどるマスで動いた先のマスのイベントは起こさない（そこで番が終わる）。ゴールを越えたらゴールになる。もどるときはスタートの次のマスまで
- ラッキー・ハプニング・すすむもどる・クイズは、リストの中から全部出るまで同じものが出ないように選ぶ。クイズの選択肢はならびを毎回まぜる
- 名所イベントに `dice` を書くとサイコロボーナスになる（例：佐渡金山）
- データの文章では `{漢字|かんじ}` と書くとふりがなになる
- ポイントが表の幅からはみ出したデータは、ゲームが幅の中に直し、画面にお知らせを出す
- 写真がまだ無い名所は「しゃしんは じゅんびちゅう」と表示する

**細かい決まり（コンテンツ追加で決定）**

- 一部のラッキー・ハプニングは場所を決めて起きる。where: "coast" は海岸線から約1kmのマスだけ、
ear: "名所のid" はその名所から3マス以内だけ
- 船よいで進むマスが1へっても、1が出たときは1マス進む（「1回休み」をつくらないため）
- 野生のトキはイベントの「つぎへ」のあとに判定する。ゴールしたときも出ることがある
- I♥佐渡は両津港の次のマス、棚田じじいは岩首昇竜棚田の2マス前、帰りたくないはゴールの1マス前に置く

## 制作フェーズ

大枠（1〜4）を10月中に終え、11月はじめはコンテンツ追加とテストに使う。本番1週間前からは新しい機能を入れず、調整だけにする。各フェーズの終わりに、実際に遊んで確認してから次に進む。

1. **動くたたき台**（目標 10/18）：地図・40マスのルート・コマ移動・サイコロ・ターン交代・ゴールと結果表示。見た目は仮でよい
2. **地図と見た目**（目標 10/25）：地図の見せ方（マス・名所の表示）、画面構成、色・フォント・コマのデザイン
3. **演出**（目標 10/28）：3Dサイコロ、跳ねる移動、カメラ追従、カウントアップ、効果音、結果発表
4. **イベントの型**（目標 10/31）：上の表の7種類を、データを書けば動く形で作る。編集モードと `HOW_TO_ADD.md` もここで作る
5. **コンテンツ追加**（11月〜、サークルで分担）：名所の文章と写真、クイズ、ラッキー・ハプニングの文章
6. **CPU**（余力があれば）：「CPUを追加」でプレイヤー枠をCPUにできる。CPUは自動でサイコロをふり、クイズはランダムに答える
7. **テストと本番準備**：小学生くらいの目線で遊んでもらい、5分に収まるかを計る。本番のPC・画面・音量・オフラインで確認する
